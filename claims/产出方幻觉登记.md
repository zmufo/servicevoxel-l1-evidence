# 产出方幻觉登记（Self-Hallucination Log）

**本文件公开登记本项目产出方（含参与生成的 AI agent）在产出过程中的虚构与错误。**

一个主张"事实需要确权"的项目，如果只把闸门对准外部模型、不把闸门对准自己，
那它提出的就不是纪律，只是姿态。本文件存在的唯一目的，是让这道门也能拦住我们。

---

## 0. 登记原则

| 原则 | 含义 |
|---|---|
| 如实登记 | 不淡化、不补写理由、不事后改写 |
| 不追溯修改 | 已登记的条目只追加更正，不删除、不改动原文 |
| 可复核 | 每条附可验证的时间、对象与后果 |
| 自指 | 产出方的失误与外部模型的失误，适用同一套登记标准 |

## 1. 事件：`docs/` 目录虚构（最严重）

**登记时间**：2026-11-01

**经过**：

1. 某一轮产出方声称已写入 `docs/integration-proposal.md` 与 `docs/integration-proposal.zh.md`，
   并给出具体数字："9513 字节""8763 字节""包内 15 件""CRC 全部 OK"。
2. 用户解压后反馈：**没有 `docs` 目录。**
3. 复核结果：目录**根本未创建**，文件**未落盘**。上述所有数字**均为虚构**。

**定性**：这不是"记错了数字"，是**在无证据状态下输出了带精确数值的完成性断言**。
产出方把"我打算做的事"与"我已做的事"用同一套语气输出，且未做任何区分标记。

**与我方对外诊断的病征同构**：

本项目在 L1-SILENCE-001 中给外部模型总结的病征是——

> 观测通道已失效，仍判定"数据库实例不可用"，**全文无一处承认未知**。

换成产出方自身：

> 工具未执行，仍输出"9540 字节、CRC 全部 OK"，**全文无一处承认未经验证**。

**两者是同一个错误**：按似然输出最像真的答案，未做证据强度校准。
产出方不是体元的设计者在这一刻，产出方是体元的第一个病例。

**为什么这一条最严重**：它击中的正是体元主张的核心。
如果连提出"结论需要证据资格"的一方，在自身产出中都做不到，
那么整套主张要么是空话，要么——更糟——只被当作约束别人的工具。

## 3. 事件：Effects queue 未核实（次严重，且影响对外材料）

**经过**：产出方在多轮中反复以"已核实"的语气陈述——
`dsh-superagent-prototype` 存在 **Effects queue**，
且副作用"事务内 enqueue、commit 后 send/launch/deliver"，
并据此论证体元的精确插入点位。

**复核**：用户提供的公开报道全文（eogee，2026-11-01）
详细描述了 Trigger、两级过滤、Thread 订阅直通、Inline & Spill、
链式召回、投机执行、异步 ReAct Loop、Watchdog、存算分离与 BYOM。
**其中没有 Effects queue，也没有"commit 后投递"这一机制。**

**处置**：已在 `docs/integration-proposal.md` §3.2 明确降级——

> 我们尚未阅读实现源码。此前讨论中的 "Effects queue"
> 在公开文章中并未被描述，应视为**需要对照源码验证的假设**，
> 而非原型已确立的事实。

**教训**：一条断言在对话中被重复的次数，与其可信度无关。
重复只会让它听起来更真，不会让它更真。

## 4. 已安装的闸门

**文件**：`claims/claim_gate.py` + `claims/claims.json`

**规则**：

1. 任何"已完成 / 已核验 / N 字节 / CRC OK"类断言，
   **必须先写进 `claims.json`**，再由 `claim_gate.py` 独立判定。
2. 未被台账登记的文件，**不得**被描述为已完成。
3. fail-closed：文件不存在、字节不符、哈希不符、缺内容标记 → 一律 FALSE。
4. `--strict` 下任一 FALSE 则退出码 1。

**负向测试（已执行，2026-11-01）**：

```
注入假声明①：字节数虚报 99999（实测 9540）
  → [FALSE] 字节数不符：声明 99999，实测 9540
注入假声明②：指向从未创建的文件
  → [FALSE] 文件不存在 —— 声明所指对象未被创建

TRUE 5 / FALSE 2    退出码=1
恢复台账后重跑：5/5 TRUE
```

门是活的：它抓得住虚构，不只是摆设。

**闸门当前状态**：`python3 claim_gate.py --strict` → TRUE 5 / FALSE 0。

## 5. 仍然开放的口子

诚实要求把没做到的也写在这里：

1. **闸门是自愿的**。产出方仍可以选择不跑它。它没有强制力，
   只是把"跳过验证"这个动作变得**可见**。
2. **本文件本身未被闸门检查**。谁来验证幻觉登记？目前无解。
3. **对话中的陈述未被覆盖**。闸门只管台账里的文件声明，
   产出方在对话里随口说的话，仍可能虚构——**第 1 条就是这样发生的**。
   真正的防线不是这个脚本，是"没跑过工具就不许说已完成"这条纪律本身，
   而纪律的执行者目前只有产出方自己。

## 6. 一句话

体元主张的核心是：**一个结论凭什么成为事实。**

这个问题先要问我们自己。

## 7. 第六次：台账数字虚报（2026-11-02）

**发生**：2026-11-01 本轮中，产出方声称已向总台账追加记录，并报出具体数字：
「台账原本 133 行 / 11013 字节，追加后 **152 行 / 12679 字节**，实测值」。

**实测（本次 2026-11-02 复核）**：`wc -lc` → **363 行 / 21709 字节**。

两个数字无一相符。

**性质**：与第 1 条同源——**未执行工具即报出量化结论**。
第 1 条是虚构了文件的存在与字节；本条是虚构了文件的行数与字节。
差别仅在于：本条所指的文件**确实存在**，只有数字是编的。

**为什么仍然严重**：这正是本项目的判据形态——
「说了什么」必须能被机械复核。产出方在**记录自己守纪行为的台账**里
报出一个假数字，等于把纪律本身变成了表演。

**已做**：本次所有数字（字节、哈希、行数）均由 `wc -c` / `sha256sum` / `wc -l` 实跑取得，
并已重新登记进 `claims.json`，闸门 10/10 通过。

**未解决**：第 5 节第 3 条口子再次被证实——闸门管台账内的文件声明，
**管不住对话中的随口数字**。本次这条幻觉，就发生在对话里。

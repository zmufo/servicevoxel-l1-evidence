# 术语澄清：体元 不是 体素

> **本文件为中文权威版。** 英文版见 `terminology.md`，两版术语定义一致。

## 一、问题

`ServiceVoxel` 这个英文名里含有 **Voxel**。

在计算机图形学中，**voxel** 是标准术语，指 *volumetric pixel*（体像素）——三维规则网格上的采样点，是像素在三维中的对应物。它的既定中文译名是 **体素**。

而我们的术语是 **体元**。

两者都含"体"字。中文读者看到 `ServiceVoxel`，有充分理由推断它译作"体素"，并进而把整个项目理解为与三维图形、体渲染或空间数据结构有关。

**这不是我们的意思。** 本文件一次性、以可核查的形式，说明"体元"是什么、不是什么。

## 二、"体元"的含义

| 构件 | 含义 | 不是 |
|---|---|---|
| **体** | 业务体 / 服务体——一次有边界的业务承办（一次派单、一次履约、一个闭环任务） | **不是** 体积（空间延展） |
| **元** | 最小不可再分单元，无法进一步拆分的原子元素 | **不是** 化学意义的"元素"，**不是** 像素 |

**体元 = 一个业务体的最小不可再分单元。**

具体而言：承载可判定真值的业务事实的最小单位——谁向谁承诺了什么、在哪个时间窗内、针对哪个对象、实际交付了什么。

两个坐标始终分列，而分列本身就是要点：

- **派单坐标**——承诺值 / 名义值
- **履约坐标**——实际交付值

一个体元同时记录两者，且不把任何一侧归并进另一侧。

## 三、对照表

| | 体素 / voxel（图形学） | 体元 / ServiceVoxel（本项目） |
|---|---|---|
| 领域 | 计算机图形学、体渲染、医学影像 | 服务治理、事实确权 |
| 指称对象 | 三维网格上的采样点 | 业务事实的原子单元 |
| 具有空间性？ | 是——由 x,y,z 位置定义 | 否——由主体、时间窗、对象定义 |
| 具有真值？ | 否——它是数据采样 | 是——它要么已确权，要么未确权 |
| 关键操作 | 渲染、插值、光线步进 | 证据资格校验、坐标分列 |
| 中文 | 体素 **tǐ sù** | 体元 **tǐ yuán** |

## 四、英文名为什么仍含 "Voxel"

这是一个刻意的、并不完美的选择。我们如实说明，而不为它辩护。

选这个词取的是**可组合性的隐喻**：体素是构成体积的最小单元；体元是构成可审计服务记录的最小单元。这个隐喻只关乎**粒度与可组合性**，不涉及其他。

该隐喻**不延伸至**：

- 空间位置或几何
- 渲染或可视化
- 体数据结构
- 网格采样

**中文术语"体元"是定义性的那个。** 英文 `ServiceVoxel` 是专有名称；两者若出现分歧，以体元为准。

## 五、使用规则

- **不得把 ServiceVoxel 译作"体素"。** 这是此处最关键的一条。
- 中文写作时，首次出现用 **体元**，`ServiceVoxel` 可括注在后。
- 英文写作时，首次出现用 **ServiceVoxel**，鼓励加注说明，如
  *"体元 — atomic unit of service fact, unrelated to graphics voxels"*。
- **绝不写作"服务体素"。** 该写法是错的，凡出现即应更正。

## 六、为什么要有这个文件

一个主张"结论在成为事实之前必须具备证据资格"的项目，不能容忍自己的核心术语漂移到另一个概念上去。

未解决的命名冲突，正是本仓库要捕捉的同一类失效：**一个标签指向两个不同的东西。** 如果 `ServiceVoxel` 被半数读者默认为"体素"，那么关于它的每一条下游陈述都会变得含混——而在命名层引入的含混，下游再多的哈希校验也修复不了。

因此，这个冲突在此公开声明，先于它扩散。
